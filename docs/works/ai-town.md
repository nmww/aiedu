# AI Town · 小镇

![AI Town](../assets/covers/ai-town.jpg)

!!! quote "一句话"
    8 位会自己走路、会互相聊天、会记事儿的 AI 居民——世界在浏览器里持续推进。

**访问站点**：[modeai-ai-town.ms.show](https://modeai-ai-town.ms.show) · **模型端**：[modeai-ai-town-ollama.ms.show](https://modeai-ai-town-ollama.ms.show)

**技术栈**：React · Vite · PixiJS · Convex · Ollama

---

## 这个项目在做什么

AI Town 是一个**智能体沙盒**：几位 AI 居民生活在一张小地图上，各自有目标、有记忆、有日程。他们会自己走路遇见彼此、发起对话、记住对方说过的话，下次见面还能接着聊。

它看起来像个游戏，实质上是一次关于**多智能体协作**的实践：怎么让多个 LLM 驱动的角色在同一世界里保持状态一致、行为合理、不互相打架。

---

## 架构：三端解耦

这是整个项目最重要的设计决策。

```
┌──────────────────────┐
│   前端空间（魔搭）      │   浏览器里的渲染与交互，纯"哑终端"
│   Vite + React        │   ——不含任何智能体逻辑
│   + PixiJS            │
└──────────┬───────────┘
           │ WebSocket
           ▼
┌──────────────────────┐
│   云端服务（Convex）    │   所有 NPC 的行为逻辑、状态、记忆
│   游戏引擎 + 状态库     │   都在这里
└──────────┬───────────┘
           │ HTTP
           ▼
┌──────────────────────┐
│   模型端（魔搭）        │   Ollama + Qwen2.5 对话
│   modeai/ai-town-ollama│   + bge-m3 嵌入
└──────────────────────┘
```

**为什么这么拆？**

前端要频繁改样式、调渲染，改完就得重新部署；模型端镜像大、启动慢，但很少动；行为逻辑改动最频繁，但每次都是纯代码变更。

绑在一起的话，改一句对话提示词都要重新构建整个前端容器。拆开之后：

- 改 AI 行为 → 部署云端逻辑，**前端完全不动**
- 改渲染效果 → 只重建前端，模型端不重启
- 换模型 → 只动模型端，其他两端无感

三端之间靠网络协议通信，各自可以独立升级。

## 模型端的技术细节

模型端跑在 **2 核 CPU、8GB 内存、无 GPU** 的规格上。这是个很受限的环境，所以做了不少调优。

**权重烘焙进镜像。** 嵌入模型（bge-m3）的权重在构建阶段就下载好并打进镜像，容器启动时不用再拉模型，冷启动时间大幅缩短。

**实测性能：**

| 指标 | 数值 |
| --- | --- |
| 生成速度 | 约 12.7 tokens/s |
| 热态首字延迟 | 0.43 – 0.9 s |
| 内存占用 | 2.07 GB / 8 GB（约 26%） |
| 输入 3000 字时首字延迟 | 约 47.6 s |

**瓶颈结论：不是内存，是 CPU 算力，而延迟的主导因素是上下文长度。**

输入从几百字涨到 3000 字，首字延迟从不到 1 秒涨到近 48 秒——因为 Transformer 的注意力计算随上下文长度增长。所以在 CPU 环境下，**控制上下文比升级配置更有效**。

**参数配置：**

| 参数 | 取值 | 原因 |
| --- | --- | --- |
| `num_ctx` | 4096 | 限制上下文长度，控制延迟；超出会静默截断 |
| `num_predict` | 256 | 限制单次生成长度，对话场景足够 |
| `NUM_PARALLEL` | 2 | 匹配 2 核 CPU，避免请求排队拖慢全部对话 |

## 前端的技术细节

**渲染与逻辑严格分离。** 前端只负责两件事：把服务端同步过来的世界状态渲染出来，把用户操作（点击居民、输入对话）发回服务端。NPC 在想什么、接下来要去哪、要不要开口说话——这些全在服务端算。

这让前端变成了可替换的一层。换一套渲染方案不需要动任何智能体逻辑。

**像素风渲染。** 用 PixiJS 做 2D WebGL 渲染，居民有行走动画、朝向、路径移动，镜头跟随，视觉上接近经典像素游戏。

## 值得记录的坑

**浏览器网页不能直连模型端。** 浏览器的跨域策略会拦住直接向模型服务发起的请求。所以模型端只接受来自服务端的调用，浏览器走前端 → 服务端 → 模型端的链路。这个约束一开始就该考虑进架构，而不是等联调时才发现。
