# QuickClass Agent · AI 智能体学习平台

![QuickClass Agent](../assets/covers/quickclass.jpg)

!!! quote "一句话"
    把「备课 → 上课 → 学情分析 → 教研沉淀」串成一条链路的 AI 课堂教学平台。

**访问站点**：[modeai-quickclass.ms.show](https://modeai-quickclass.ms.show) · **技术栈**：Next.js · TypeScript · Prisma · SQLite · LLM

---

## 解决什么问题

一线老师用 AI 的障碍从来不是「没有工具」，而是工具是散的：

- 出题用一个网站、做互动页面用一个工具、收作业用微信群、统计分析靠手工；
- AI 对话内容留不下来，第二节课不知道上节课学生卡在哪；
- 教研想写论文，但课堂过程性数据根本没有结构化留存。

QuickClass 的思路是**把一节课的完整生命周期装进一个系统**——老师建一次课堂，后面所有环节的数据自动串起来。

## 核心功能

### 教师端

| 模块 | 说明 |
| --- | --- |
| **课堂管理** | 创建课堂、绑定班级、设置课堂目标；支持启用 / 停用与排序 |
| **AI 对话活动** | 预设对话主题，学生与 AI 围绕主题对话；支持 AI 优化课堂目标、AI 优化学情描述 |
| **互动探究** | 由 AI 生成 HTML 互动探究页面（如模拟实验、参数调节），学生操作过程可记录 |
| **课堂测验** | 出题、发布、自动批改，生成答题报告与统计数据 |
| **项目提交** | 学生作品提交与班级展示墙，支持点赞、置顶 |
| **知识仓库** | 上传教学资料构建专属知识库，AI 对话结合备课资料开展个性化导学（RAG） |
| **学情分析** | 基于真实课堂数据生成个人 / 班级学情分析报告，含可视化数据大屏 |
| **教学研究** | 基于冻结快照的课堂原始数据，一键生成教研论文 |
| **优秀课例库** | 精选课例一键导入到自己的课堂，导入即启用、自动去重 |
| **导入导出** | 课堂配置一键导出 / 导入，实现教学资源复用 |
| **教学手册** | 一键导出教师教学手册与学生打印版学案 |
| **AI 朗读** | 文字转语音（TTS），可朗读题目与 AI 反馈 |

### 学生端

对话思考、互动探究、答题、作品提交、学习进度与个人学情报告、学习评价。

## 技术架构

```
┌──────────────┐   ┌──────────────┐
│  教师端 Web   │   │  学生端 Web   │
└──────┬───────┘   └──────┬───────┘
       │  Next.js App Router / TypeScript
       ▼                  ▼
┌─────────────────────────────────────┐
│        API 路由层（鉴权 + 业务）      │
├─────────────────────────────────────┤
│  LLM 适配层 ── OpenAI 兼容接口        │
│  ├─ 平台模型（环境变量注入）           │
│  └─ 自配置模型（系统设置，DB 优先）     │
├─────────────────────────────────────┤
│  Prisma ORM  →  SQLite               │
└─────────────────────────────────────┘
```

**部署形态**：Docker 单容器。构建阶段一次性完成依赖安装 → Prisma 建库 → 演示数据填充 → `next build`，运行阶段只跑最小启动命令。

## 值得说的几个设计

**平台模型与自配置模型的双轨兼容。**
系统既支持在「系统设置」里填自己的 API Key，也支持从平台环境变量读取默认模型。当用户选择「一键切回平台默认模型」时，配置层会自动回退到环境变量提供的服务——保证演示环境开箱可用，也让私有化部署有地方填自己的 Key。

**导入的幂等性。**
优秀课例「导入到我的课堂」如果反复点击，早期版本会重复创建课堂。现在课堂记录上会存下来源课例 ID：同一课例重复导入时直接返回已存在的课堂，不再新建；界面加载时也会根据后端返回的已导入集合把按钮置灰。**状态存后端，不存浏览器。**

**冻结快照做教研。**
生成教研论文时，不是实时查询当前数据库，而是对学生学习数据做一次冻结快照。这样论文写作期间数据变动不会导致结论漂移，也让结果可复现。

## 遇到过的坑（记录一下）

**网关会剥离 `Authorization` 请求头。** 部署平台的网关层只放行 `x-auth-token`，前端用标准 `Authorization: Bearer` 发的鉴权请求会被静默吃掉，接口全部返回 403——表现成「下拉框是空的」「功能用不了」，很容易误判成业务 bug 去查后端逻辑。后端其实早就做了双读兼容，问题全在前端传输层。

**对象键含连字符必须加引号。** 从 `Authorization` 改名为 `x-auth-token` 时，前者是无连字符的合法标识符可以直接当对象键；后者含连字符，裸写 `x-auth-token: ...` 会被 JavaScript 解析成减法表达式 `x - auth - token`，整个构建直接失败。正确写法是 `"x-auth-token": ...`。

这两条后来都固化进了部署检查清单。
